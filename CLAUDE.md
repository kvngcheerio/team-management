# Matchday — notes for future sessions

- Business rules live only in `src/shared/rules.ts` (pure, tested in `test/rules.test.ts`). Server routes and UI must call it rather than re-implement scoring.
- Day-scoped writes go through `commitDay()` in `src/worker/lib/matchday.ts`: version guard + `_batch_guard` CHECK trick to abort/rollback a D1 batch when a conditional UPDATE matches 0 rows. Finalized-day corrections pass `recompute: state` (post-change in-memory `DayState`) so `day_player_stats` is replaced in the same batch.
- Capacity is enforced in single SQL statements (`CAPACITY_STATUS` in routes/matchdays.ts) — don't split into read-then-write.
- Tests: `@cloudflare/vitest-plugin` (not vitest-pool-workers); storage persists across tests within a file, isolated per file. Call the worker with `exports.default.fetch` (helpers in `test/helpers.ts`). Each test client gets a distinct `CF-Connecting-IP` to avoid tripping rate limits.
- Better Auth runs per-request with `database: env.DB` (native D1). Public `/api/auth/sign-up/*` is blocked; accounts come from `/api/setup` or invite acceptance (server-side `auth.api.signUpEmail`). Passwords use PBKDF2 via WebCrypto (100k iterations is Cloudflare's max).
- Vite 8 is required by `@vitejs/plugin-react` 6; build output is `dist/client` + `dist/worker`.
- Demo seed: `scripts/demo-seed.ts` runs with Node's native TS support and imports rules.ts directly (keep rules.ts free of TS-only runtime syntax such as enums).
- Verify with `npm run check`; UI with `npm run dev` + `npm run db:seed:demo` (wipes local DB).
- `wrangler d1 create` can auto-append its own d1 entry (binding `matchday_db`, `"remote": true`). The code needs binding `DB`; `remote: true` would point local dev at production. Symptom of a wrong binding: every DB route returns the generic 500.
- Team sheet visibility is enforced server-side in `buildDetail` via `teamSheetVisible()` (rules.ts); members get `sets: []` before `match_days.team_sheet_at`.
- Payments are a dummy provider (`routes/discipline.ts`); success uses a `changes() = N` guard so all fines flip to paid atomically or nothing does. Replace `/payments/:id/simulate` with a verified provider webhook to go live.
- Weekly MVP polls are created inside the finalize batch (`matchdayPollStatement`). Results are hidden while open, even from admins.
- Tailwind: override `Input`/`Select` width with `!w-auto` (base class has `w-full`).
- Access model (migration 0004): signups are guests; guest fee per match day on `registrations.fee_status` (free after N paid days per season, `lib/access.ts`); membership via `membership_payments`; wallet is an append-only `wallet_transactions` ledger with unique `ref` (referral credit once per invitee). All checkouts go through `routes/payments.ts` `completionStatements()`.
- Editing an already-applied migration requires `npm run db:reset:local` locally; never edit migrations that `wrangler d1 migrations list --remote` shows as applied.
- After `npm install` while `npm run dev` is running, restart it with `--force`: a stale Vite dep cache leaves the page blank with no console error ("Failed to fetch dynamically imported module").
- `wrangler.jsonc` is TAB-indented: scripted edits must match tabs and assert the match (a silent miss once dropped the cron trigger). After deploy, confirm both `schedule: 0 5 * * *` and `*/15 * * * *` appear in the wrangler output.
- Production: primary origin https://game.pluvialhq.com (`BETTER_AUTH_URL` secret); workers.dev kept via `APP_ORIGINS`.
- Email (migration 0006): Email is Resend only (user's choice): `lib/email.ts` `sendEmail()` posts to Resend's API with the `RESEND_API_KEY` secret; no Cloudflare send_email binding. Sender = `EMAIL_FROM` var (domain must be verified in Resend). Tests stub `fetch` for api.resend.com. Layout: `lib/email-layout.ts`; preview/test-send at Admin → Schedule. Sender = `EMAIL_FROM` var. Check-in reminders (`lib/reminders.ts`) run from the `*/15` cron on match day, 2h before kick-off, only while check-in is still open (`scheduled()` dispatches on `event.cron`); `email_log` UNIQUE row is claimed before sending (failed rows are retried). Players opt out via `players.email_reminders`.
- Check-in deadline is soft: self check-in is allowed while `status = 'checkin_open'` (`lateCheckInAllowed`), and check-ins after `checkin_deadline` set `registrations.checked_in_late = 1` for later enforcement. Withdrawing / "can't make it" while holding a place still closes at the deadline (`selfCheckInOpen`). The public guest form still uses the hard deadline.
- Late placement: when a player becomes `confirmed` after teams are published (self check-in, admin add, approve/promote/restore, guest fee paid online or marked paid/waived), `autoPlaceInTeam()` (`lib/matchday.ts`) adds them via `chooseSetForLatePlayer` (rules.ts): smallest set as starter, else sub. It runs as a separate `commitDay` after the registration (retries on version conflict, never throws), so any new path that confirms a registration must call it too.
- Placement points (migration 0007): league points follow set placement, `placementPoints(setCount)` in rules.ts (4+ sets 3/2/1, 3 sets 3/1/0, 2 sets 3/0); `daySetPlacements` places sets below the daily winner(s) by regular wins then goal difference; sets level on both share position and points. `daily_win` still marks only the winner. 0007 rebuilt `day_player_stats` to `CHECK (points BETWEEN 0 AND 3)`: apply it remotely BEFORE deploying code that awards 1 or 2, or finalize fails the CHECK.
- Forgot password: Better Auth `emailOTP` plugin (`auth.ts`), but only `/auth/email-otp/request-password-reset` (5/15min/IP) and `/auth/email-otp/reset-password` (10/15min/IP) are reachable; index.ts 404s OTP sign-in and the other plugin routes. Code email is `lib/password-reset.ts`, sent via `waitUntil` (`backgroundTasks`) so response time doesn't reveal whether an account exists. Reset revokes all sessions. Codes are hashed in `verification` (no migration). UI: `/forgot-password`.
- Offline/PWA: `public/sw.js` caches only the app shell (never `/api`); registered in production builds only. Last API data is saved to localStorage by `offline-cache.ts` (signed-in data only; cleared on sign-out). Offline writes go through `useQueuedDayMutation` → `outbox.ts` (localStorage, FIFO, replayed on reconnect) for check-in/unavailable, start, matches, goals, scorer, cards, attendance only. Any endpoint added to the queue must be replay-safe (client id, upsert, absolute value, or `doneStatuses`) and get an `offlineApply` patch so the screen updates. Replays use server arrival time (late check-ins count as late). Install guide: `/install`; Android install prompt captured in `install.ts`. Push notifications not built yet.
- Guests in teams: `PoolPlayer.guest` / `SetFill.guests` drive even guest spread (`balancedTeams`/`randomTeams` place guests before members; late placement breaks size ties by guest count). Any new pool/fill builder must set these from `players.kind` or guests stack again.
- Guests are hidden from shared boards for non-admins (`seasonTables(..., { includeGuests })`, `/seasons/:id/stats`); profiles still show their stats, and season totals still count their goals/cards.
